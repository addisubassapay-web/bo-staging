# RCA — "Publish" spinner stuck forever on `ocean-marketplace`

## Verdict
**None of hypotheses (1), (2), or (3) is the active cause.** The real root cause is that **this deployment has been shut down** — its state is `deployment_status = deleted`, `suspension_reason = user_shutdown`. A shut-down deployment does not accept new deploys, so the Publish clicks never materialize into a pipeline run, and the UI has nothing to resolve the spinner against.

## Evidence (read directly from the pipeline)
- Deployment `ocean-marketplace` (`ac63a18e-0bed-49ae-80ff-170e3af84404`): `deployment_status = deleted`, `suspension_reason = user_shutdown`, updated `2026-09-05T04:35:54Z`.
- `active_run_id = e6039561-…` — a **successful** `redeploy` (trigger `secret_change`) that completed **2026-09-02T20:08:44Z**. This is the last run that executed.
- The three "deployment initiated" notifications from the last ~10 minutes produced **no DeployRun** — the newest entry in run history is still the 9/02 success. The clicks are not creating runs.

## Hypotheses, tested
1. **Trust & Safety phishing classifier silently rejecting the build — NOT the current cause.** There was exactly one phishing block in history: run `7c4b1265-…` (2026-08-31T21:10Z) failed on `AwaitPhishingClassification` with: *"deployment blocked: there has been an error with this deployment. Please fork the session and start a new deployment."* But **two subsequent runs on 2026-09-02 (`07cd9627` replacement and `e6039561` redeploy) both succeeded**, which means the classifier cleared this app afterward. It is not blocking today, and the current symptom is not a silent classifier failure. (Also note: a real classifier block surfaces as a **failed run**, as it did on 8/31 — not as an indefinite spinner.)
2. **Concurrent deploy deadlock — no supporting evidence.** There are zero in-flight/queued runs; the three clicks created no runs to contend with each other.
3. **Success webhook dropped to the UI — no supporting evidence.** Nothing succeeded in the last 10 minutes; the most recent success is the 9/02 run. There is no completed-but-unreported pipeline.

## Why the spinner never resolves
The deployment is `deleted` (user_shutdown). The publish trigger has no live deployment to attach to, so no run is created and no terminal state is ever emitted — the UI waits forever. This is a state problem, not a build/classifier/queue problem.

## Remediation
- The app was **shut down by user action**. To publish again the user must **start a fresh deployment / re-create the deployment** from the Publish panel (a deleted deployment cannot be resumed in place). If the panel keeps spinning on the deleted deployment, refresh/relaunch the publish flow so it creates a new deployment rather than targeting the shut-down one.
- **No Trust & Safety whitelist action is required** — the classifier already passed this app on 9/02 after the rebrand. There is no active T&S block to route to a human.
- I have **no tool to un-delete/restore a shut-down deployment or to redeploy it**; that is a UI/platform action for the user.

## Note on preview
Preview health being green (`/api/health` 200, 37/37 tests) is consistent with everything above — the code is fine. The blocker is purely the deployment's shut-down lifecycle state, which is independent of source health.
