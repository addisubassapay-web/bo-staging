# RCA — ocean-marketplace deploy blocked (HTTP 409 deployment_blocked)

## Summary
The committed deploy run could not start. The `trigger_indie` step returned **HTTP 409 `deployment_blocked`** (non-retryable). This is a **platform-level block on the deployment**, not a build/manifest/source failure. No pipeline retry can clear it.

## Evidence
- `describe_deployment_state`:
  - `deployment_status = deleted`
  - `suspension_reason = user_shutdown`
  - `deployment_name = ocean-marketplace`, `deployment_id = ac63a18e-0bed-49ae-80ff-170e3af84404`
- `trigger_indie` error envelope:
  - `status 409: {"code":"deployment_blocked","error":"This deployment was blocked. If you believe this is a mistake, please contact support."}`
  - `kind: indie_trigger_failed`, `retryable: false`
- Run history corroborates: run `7c4b1265-0ac8-4c11-bc31-0b426b1d5f9c` (2026-08-31) failed at `AwaitPhishingClassification`:
  - *"deployment blocked: there has been an error with this deployment. Please fork the session and start a new deployment."*

## Root cause
The deployment has been shut down (`user_shutdown`) and is flagged/blocked at the platform level (consistent with a prior phishing-classification block). The indie deploy endpoint rejects all new runs for it with a non-retryable 409.

## Why no retry / no fix was applied
- The 409 is explicitly `retryable: false`; `resume_pipeline` would re-issue the same blocked request and fail identically.
- There is no manifest, Dockerfile, or source change that can lift a platform-level block.

## Remediation
1. **Platform/Support (Emergent):** Review the block/phishing flag on deployment `ocean-marketplace` (`ac63a18e-0bed-49ae-80ff-170e3af84404`). If it is a false positive, clear the block.
2. **User:** Contact Emergent support quoting deployment_id `ac63a18e-0bed-49ae-80ff-170e3af84404` and job_id `c723d6ce-a63e-4188-9be8-0d6f8f1cca71`. If advised, fork the session and start a fresh deployment as the earlier error suggested.
