# RCA — ocean-marketplace "Deployment initiated" infinite loop

## Summary
The deploy pipeline cannot go live because the **deployment record is in a `deleted` lifecycle state with `suspension_reason = user_shutdown`**. Every "Take your app live" click enqueues a run and fires a "Deployment initiated" notification, but a deleted/shutdown deployment never executes the pipeline — so nothing promotes and the Publish button spins on "Loading..." indefinitely. This is a platform lifecycle/T&S gate, NOT a code, build, credits, or resource problem.

## Evidence (from describe_deployment_state + get_step_status)
- `deployment_status: "deleted"`
- `suspension_reason: "user_shutdown"`
- `billing_plan: "monthly"` (no credit/subscription exhaustion signal)
- `active_run_id: e6039561-...` — last successful run, `run_status: success` (a healthy image exists; app was live before shutdown)
- Recent run history: 4 successful production runs (initial `337848f7`, redeploy `5248ac9c`, replacement `07cd9627`, redeploy `e6039561`) — code builds and goes live fine.

## The one run that reached the pipeline and failed — 7c4b1265 (Aug 31)
Step trace:
- `wakeup_environment` — success
- `build` — **success** (code compiles; image built)
- `mongodb_migrate` / `manage_secrets` / `deploy` / `health_check` — "not run: an earlier deploy step failed" (pods never started → no pod logs exist)

Verbatim failure:
```
await_phishing: activity error (type: v3.InitialDeploy.AwaitPhishingClassification,
scheduledEventID: 60, startedEventID: 61, identity: 1@deployer-v3-v0-8-102-...):
deployment blocked: there has been an error with this deployment.
Please fork the session and start a new deployment (type: wrapError, retryable: true):
deployment blocked
```
The deploy was hard-blocked at the **AwaitPhishingClassification** gate, before any Kubernetes rollout. The platform's own instruction in this error is: *fork the session and start a new deployment* — i.e. this session/deployment is permanently gated and retrying the SAME one will keep looping.

## Why the loop persists
The user keeps retrying the same shut-down / T&S-gated deployment. A `deleted`/`user_shutdown` deployment can never promote, and the phishing gate on this session is sticky. Repeated clicks only re-enqueue → repeated "Deployment initiated" notifications with no result.

## Code readiness (question 4)
PASSING. Health probes `/health` and `/api/health`, keep-alive, and absence of phishing strings are not the blocker — four prior production runs went live and the Aug 31 run's build succeeded. No code change is required.

## Remediation (no agent tool can reverse either gate)
1. **Platform (Emergent) must act** — reverse the `user_shutdown`/`deleted` lifecycle state AND clear the AwaitPhishingClassification block on this deployment/session. Neither is reversible from the deployer agent toolset or from the UI.
2. **User** — per the platform's own error text, **fork the session and start a NEW deployment** rather than retrying the deleted one; and email support@emergent.sh with the specifics below so the block/shutdown can be lifted.
